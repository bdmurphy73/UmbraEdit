# AI Policy

This is the AI policy of UmbraEdit and associated projects.

### Philosophy
I'm not a top level programmer, but I have ideas for programs and projects. I focus on what will help me and AI will help me realize these programs.

I act as the product manager and use AI to build do basic testing. The project needs to meet my needs and I will test it.

UmbraEdit is focused on creating, editing and publishing book in ePub, print and audio formats. I write the books, not AI, then I want to use AI to do the rest of the work.

AI is a tool. Just like a compiler is a tool. It isn't going away.

I forked the original novelWriter to make UmbraEdit because the novelWriter policy was to not use AI at all. 
I'm also taking the base/original idea of novelWriter and extending it into the system I want. 
That is why we all use GPL, to share and make our own version of the project.  

The ideas:

1. Write the novel. Make it simple while writing. Formatting is later.
2. Have the entire project together. Not the novel text here and metadata you need somewhere else. All together. 2.a) ePub, paperback (print pdf), audio all start with the same story text, but each needs something different. Put everything into one project (ISBNs, book blurb, search terms, genere/categories BISAC codes, cover, etc)
3. With everything together formatting and publishing is simpler
4. The goal is to write (human written) a novel, then use AI to help with everything else. At the end of the process there will be ePub, Paperback/Hard cover, audio versions in 10 languages.

### Code Contributions

Code contributions start with an idea that is expressed in a specification or markdown file. If I take your spec and use a different AI at a different time the implementations will probably be different. Just like I won't tell you how to write and comment you code I won't be anal  and nitpick the way AI creates the code.  The AI should follow the CODING_STANDARD.md

The original work is still there. Things are changed when needed for the new functionality. I'm also trying to support all the languages originally supported, but I don't know how well the translations will turn out. We consider code to be creative work, and we have a strong preference for feature contributions designed by actual
humans over the average and mediocre output of agentic and generative AI.

### Design Work

Visual elements must follow the design already published, using the Umbra brand.

### Translation Work

Translations should be identified by the contributor, human or AI. The humans get credit for their work.

### Application Features

There are and will not be tools to generate stores. Features will be added to help the author in writing, not write the story.

### Discussions and Comments

Please refrain from using AI to generate or respond to discussions, issues, and pull requests. Especially do not use AI
tools to generate long and verbose issue reports. It is OK to use AI for translations of comments or for accessibility
reasons. All text in the code or posted to this project must be in English.
