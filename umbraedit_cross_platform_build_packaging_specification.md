# UmbraEdit Cross-Platform Build & Packaging Specification

## 1. Project Overview & Architecture Context
* **Application Name:** UmbraEdit (Fork/Extension of `novelWriter`)
* **Core Stack:** Python 3.10+, PyQt6, `uv` (dependency management), `pkgutils.py` (asset/translation/icon compiler).
* **Host Development Environment:** macOS (Apple Silicon / Intel).
* **Target Distribution Artifacts:**
  1. **macOS Disk Image (`.dmg`)** — Native `.app` bundle inside a styled `.dmg`.
  2. **Windows Executable Installer (`-setup.exe`)** — Standalone frozen executable wrapped in an Inno Setup installer.
  3. **Linux Debian Package (`.deb`)** — Architecture-specific Debian package containing a frozen binary or isolated virtual environment + desktop integration.
  4. **Checksums (`.sha256`)** — SHA-256 verification files for every generated artifact.

---

## 2. Pre-Build Asset & Source Preparation (All Targets)
Before compiling binaries for *any* target OS, the build pipeline must compile novelWriter/UmbraEdit's internal runtime assets using the repository's native build helper (`pkgutils.py`):

1. **Sync Dependencies:**
   ```bash
   uv sync
   ```
2. **Compile Qt Translations & Icons:**
   ```bash
   uv run python pkgutils.py qtlrelease
   uv run python pkgutils.py icons default
   ```
3. **Branding & Metadata Verification:**
   * Ensure `novelwriter/__init__.py` (or the equivalent UmbraEdit package metadata) reflects the version string (e.g., `26.2.2` or UmbraEdit's semantic version) and application name `UmbraEdit`.
   * Ensure `QApplication.setApplicationName("UmbraEdit")`, `QApplication.setApplicationDisplayName("UmbraEdit")`, and `QApplication.setDesktopFileName("umbraedit")` are explicitly called **before** `QApplication` window instantiation in the main entry point (`novelWriter.py` / `UmbraEdit.py`).

## 3. Target 1: macOS `.dmg` & `.app` Bundle (Native Build)

### 3.1 Root Cause of the "Python" Menu Bar & Dock Bug
When launching a Python/PyQt6 script via a wrapper shell script or an improperly configured bundle, macOS LaunchServices reads the `Info.plist` of the underlying `Python.app` framework binary rather than the application bundle. This causes:
* The top-left macOS menu bar to display **Python** instead of **UmbraEdit**.
* A terminal window or generic Python rocket icon to bounce in the Dock.
* macOS Gatekeeper/TCC permissions (Documents/Desktop folder access) to be requested under "Python".

### 3.2 Mandatory macOS User Startup Experience
1. **Zero Terminal Flash:** Double-clicking `UmbraEdit.app` (or opening via Spotlight/Launchpad) must launch the GUI directly without opening `Terminal.app` or a console subprocess.
2. **Native Menu Bar Identity:** The bold application menu item next to the Apple (``) icon must read **UmbraEdit**, with standard native submenus (`About UmbraEdit`, `Settings...`, `Quit UmbraEdit`).
3. **Dock & App Switcher (`Cmd+Tab`):** Must display the high-resolution `UmbraEdit.icns` icon and the label `UmbraEdit`.
4. **File Association & Launch:** Dragging a `.nwd` or `.nw` project folder onto the Dock icon, or double-clicking a project file, must pass the file path via macOS AppleEvents (`QEvent.FileOpen`) directly into the running UmbraEdit instance.

### 3.3 Technical Implementation Requirements (macOS)
* **Tooling:** `PyInstaller` (run natively on macOS) + `create-dmg` (or `hdiutil`).
* **Entry Point & Freezing:**
  * Must build in `--windowed` (`-w`) / `--onedir` mode wrapped in a `.app` bundle (`BUNDLE` in `.spec`). Do **not** use `--onefile` for macOS `.app` bundles, as it causes slow extraction delays on startup and breaks code-signing.
  * The binary inside `UmbraEdit.app/Contents/MacOS/UmbraEdit` must be a compiled Mach-O executable generated by PyInstaller—**never** a `#!/usr/bin/env python3` shell script.
* **Mandatory `Info.plist` Keys:**
  The PyInstaller `.spec` file must inject the following dictionary into `BUNDLE(..., info_plist={...})`:
  ```python
  info_plist = {
      "CFBundleName": "UmbraEdit",
      "CFBundleDisplayName": "UmbraEdit",
      "CFBundleExecutable": "UmbraEdit",
      "CFBundleIdentifier": "io.umbraedit.app",
      "CFBundleVersion": VERSION,
      "CFBundleShortVersionString": VERSION,
      "CFBundlePackageType": "APPL",
      "LSMinimumSystemVersion": "12.0",
      "NSHighResolutionCapable": True,
      "NSSupportsAutomaticGraphicsSwitching": True,
      "LSApplicationCategoryType": "public.app-category.productivity",
      "CFBundleDocumentTypes": [
          {
              "CFBundleTypeName": "UmbraEdit Project",
              "CFBundleTypeRole": "Editor",
              "LSHandlerRank": "Owner",
              "CFBundleTypeExtensions": ["nw", "nwd", "nwx"],
          }
      ],
  }
  ```
* **Icon Generation:**
  * Convert the master SVG/PNG logo into a multi-resolution `.icns` file (`icon_16x16.png` through `icon_512x512@2x.png`) using `iconutil -c icns` during the build script.
* **Ad-Hoc Code Signing (Critical for Apple Silicon):**
  * After PyInstaller generates `dist/UmbraEdit.app`, re-sign the bundle so macOS Apple Silicon does not kill the process with `SIGKILL (Code Signature Invalid)`:
    ```bash
    codesign --force --deep --sign - dist/UmbraEdit.app
    ```
* **DMG Packaging:**
  * Generate `UmbraEdit-<version>-macos-<arch>.dmg` containing `UmbraEdit.app` and a symlink to `/Applications`.
  * Recommended command:
    ```bash
    create-dmg \
      --volname "UmbraEdit Installer" \
      --window-pos 200 120 \
      --window-size 600 400 \
      --icon-size 100 \
      --icon "UmbraEdit.app" 175 190 \
      --hide-extension "UmbraEdit.app" \
      --app-drop-link 425 190 \
      "dist/UmbraEdit-${VERSION}-macos.dmg" \
      "dist/UmbraEdit.app"
    ```

## 4. Target 2: Windows Executable Installer (`-setup.exe`) from macOS

### 4.1 Cross-Compilation Strategy on macOS
PyInstaller **cannot** natively cross-compile Windows PE (`.exe`) binaries directly on macOS because it bundles the host OS's Python shared libraries and PyQt6 DLLs. To build the Windows installer reliably from a macOS host, the build script must use **Docker (with Wine + Windows Python)** or **automated Wine prefix execution**:
* **Preferred Method (Deterministic & Clean):** Docker container running `tobix/pywine` or a custom Ubuntu + Wine64 image pre-loaded with Windows Python 3.12, `PyQt6`, `pyinstaller`, and `Inno Setup 6` (`ISCC.exe`).

### 4.2 Windows User Startup & Install Experience
1. **Installer (`UmbraEdit-<version>-amd64-setup.exe`):**
   * Standard Inno Setup wizard (matching `novelWriter`'s setup UX).
   * Supports per-user installation (no UAC admin prompt required if installed to `%LOCALAPPDATA%\Programs\UmbraEdit`) or system-wide installation (`Program Files`).
   * Creates Start Menu shortcuts, optional Desktop shortcut, and registers `.nwx` file associations.
2. **Application Startup:**
   * Launches `UmbraEdit.exe` with `console=False` (GUI subsystem—no black `cmd.exe` window).
   * Displays the UmbraEdit taskbar icon (`UmbraEdit.ico`) and sets a distinct Windows `AppUserModelID` (`ctypes.windll.shell32.SetCurrentProcessExplicitAppUserModelID("UmbraEdit.Editor.App")`) so Windows groups windows properly on the taskbar instead of grouping under Python.

### 4.3 Technical Implementation Requirements (Windows)
* **Build Steps (Executed inside Wine/Docker container):**
  1. Install dependencies in Windows Python environment:
     ```bash
     wine python -m pip install -r requirements.txt pyinstaller
     ```
  2. Freeze application using PyInstaller (`--windowed`, `--onedir`, `--icon=setup/umbraedit.ico`, `--name=UmbraEdit`).
  3. Compile the Inno Setup script (`setup/win_installer.iss`) using Inno Setup CLI:
     ```bash
     wine "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" /DMyAppVersion=${VERSION} setup/win_installer.iss
     ```
  4. Output final installer to `dist/UmbraEdit-${VERSION}-amd64-setup.exe`.

## 5. Target 3: Linux Debian Package (`.deb`) from macOS

### 5.1 Cross-Compilation Strategy on macOS
To build a valid Linux `.deb` package on macOS without broken Mach-O binaries or invalid `tar` metadata, the build script must execute inside a **Linux Docker container** (`--platform linux/amd64` and optionally `linux/arm64` via Docker Buildx):
* **Base Image:** `ubuntu:22.04` or `debian:bookworm-slim` (ensuring broad `glibc` compatibility across Debian, Ubuntu, and Linux Mint).

### 5.2 Linux User Startup & Install Experience
1. **Installation:** User installs via `sudo apt install ./UmbraEdit-<version>-amd64.deb` or double-clicks in GNOME Software / KDE Discover.
2. **Desktop Integration:**
   * Appears immediately in the system application launcher under **Office / WordProcessor / Utility** with the scalable SVG icon (`umbraedit.svg`).
   * Launching from the application menu or running `umbraedit` in the terminal starts the GUI cleanly.
   * Wayland & X11 Window Matching: `StartupWMClass=UmbraEdit` in the `.desktop` file must match `QApplication.setDesktopFileName("umbraedit")` so the dock/panel displays the UmbraEdit icon rather than a generic Wayland/X11 gear icon.

### 5.3 Technical Implementation Requirements (Linux `.deb`)
* **Build Steps (Executed inside Linux Docker container):**
  1. Freeze the application with PyInstaller (`--onedir`, `--name=umbraedit`) so all PyQt6 shared libraries and Qt plugins (`xcb`, `wayland`) are self-contained and isolated from system Python version mismatches.
  2. Stage the Debian directory tree in `/tmp/deb_build`:
     * `/opt/umbraedit/` — Contains the PyInstaller bundle (`umbraedit` executable + `_internal/`).
     * `/usr/bin/umbraedit` — Symlink pointing to `/opt/umbraedit/umbraedit`.
     * `/usr/share/applications/umbraedit.desktop` — XDG Desktop Entry.
     * `/usr/share/icons/hicolor/scalable/apps/umbraedit.svg` — Application icon.
     * `/usr/share/mime/packages/umbraedit.xml` — Custom MIME type registration for `.nwx` project files.
     * `/DEBIAN/control` — Package metadata (`Package: umbraedit`, `Version`, `Architecture: amd64`, `Maintainer`, `Depends: libgl1, libegl1, libxkbcommon-x11-0, libdbus-1-3`, `Description`).
     * `/DEBIAN/postinst` — Runs `update-desktop-database` and `update-mime-database`.
  3. Build the `.deb` archive with root ownership flags:
     ```bash
     dpkg-deb --root-owner-group --build /tmp/deb_build "dist/umbraedit_${VERSION}_amd64.deb"
     ```

## 6. Master Build Automation Script (`build_all.py` / `Makefile`)
The LLM implementing this specification should create a unified build orchestration script (e.g., `build_releases.py` or a `Makefile`) in the repository root that supports building targets individually or all at once:

```bash
# Expected CLI Interface
python3 build_releases.py --version 1.0.0 --target macos
python3 build_releases.py --version 1.0.0 --target windows
python3 build_releases.py --version 1.0.0 --target linux
python3 build_releases.py --version 1.0.0 --target all
```

### 6.1 Required Output Directory Structure (`dist/`)
Every build run must produce clean, standardized artifacts along with SHA-256 checksums:
```text
dist/
├── UmbraEdit-1.0.0-macos-universal.dmg
├── UmbraEdit-1.0.0-macos-universal.dmg.sha256
├── UmbraEdit-1.0.0-amd64-setup.exe
├── UmbraEdit-1.0.0-amd64-setup.exe.sha256
├── umbraedit_1.0.0_amd64.deb
└── umbraedit_1.0.0_amd64.deb.sha256
```

### 6.2 Post-Build Automated Verification Checklist
The LLM must include automated verification checks at the end of each build target:
1. **macOS Check:** Inspect `UmbraEdit.app/Contents/Info.plist` using `plutil -p` to verify `CFBundleName == "UmbraEdit"` and `CFBundleExecutable == "UmbraEdit"`, and verify `file UmbraEdit.app/Contents/MacOS/UmbraEdit` returns `Mach-O 64-bit executable` (not a text/shell script).
2. **Windows Check:** Verify `UmbraEdit-<version>-amd64-setup.exe` exists, is non-empty (`> 40 MB`), and passes `file` check as `PE32+ executable (GUI) x86-64, for MS Windows`.
3. **Linux Check:** Run `dpkg-deb --info dist/umbraedit_<version>_amd64.deb` and `dpkg-deb --contents` to confirm valid control metadata and file permissions (`0755` on binaries).
